# 记录与同步约束

## 本地写入与后台队列

- 体验记录写入工作流共用 `pist.records.lock.record_writer_lock`，以同一数据目录的跨进程排他锁防止并发覆盖；新入口须在读取编辑快照前获取，并保持至工作流退出。此约束不保护直接存储调用；需要并行编辑时另行设计记录级冲突检查。测试使用隔离的数据目录，并覆盖正常退出、异常和进程终止后的释放。
- UI 与 CLI 的记录同步统一经由 `RecordSyncService`，不得直接按地图名选择远端行或提供跳过核对的写入旁路。首次新增先持久化尝试，获得远端 ID 后原子保存关联并解除尝试；不确定的新增不能因名称变化、重启或网络恢复而自动重试。
- UI 打开编辑及取消编辑不请求表格，字段选项可复用本地最近读取的 schema，但不将其作为当前远端兼容性的证据。编辑确认后先保存本地，再交给独立的串行同步队列，提交前首次实时核对字段与目标记录，并按确认基准处理冲突，不让新编辑任务取消旧写入。后台人工交互须等待前台编辑结束，同一排队记录暂不重复编辑；显式同步与改号等待队列完成后读取最新本地内容。取消同步不撤销已保存的编辑；正常退出前提示未完成队列，异常中断保留本地待推送状态与新增保护。

## 作者候选与网络生命周期

- GameBanana 作者候选同时展示 Credits 的分组、角色及 Submitter 来源，由用户明确选择；提交者不自动认定为作者，同名来源可分别展示，保存的作者姓名去重。
- Berries 仅提供 Credits、角色和 Submitter 等事实；作者选择项的语言、标签与 UI 元组由 Pist 编辑界面生成，不向公共模型添加个人展示策略。
- 网络客户端通过显式异步上下文在同一工作流内复用连接，退出时关闭；未进入上下文的单次调用仍自行关闭资源。表格定位在工作流内固定到已解析的文件与主表 ID，不缓存用于核对的字段或单元格，每次核对仍读取实时内容；读取失败后丢弃定位缓存，不自动重试。GameBanana 成功查询和未匹配结果默认短期缓存五分钟，可显式清除或禁用，失败不缓存；不得将元数据缓存用于替代表格冲突核对。

## 状态、核对与响应确认

- 记录状态显示为“无本地变更”“待推送”“待核对”，不暗示持续监测远端。UI 的最近核对时间列复用关联中的确认时间，按系统本地时区展示；本地编辑、刷新列表或仅读取远端快照不推进确认时间。一键同步核对全部本地记录，不跳过无本地变更记录；取消或失败时仅统计本次已处理且确认的记录，不以旧状态判定本次成功。
- 已关联记录核对时，远端相对基准的变化若已与本地待写值一致，该字段不构成冲突，不掩盖其他字段的真实冲突。重新核对后，所有待写字段均与远端一致时直接确认并刷新基准，不为推进同步状态重复写入；读取快照本身不推进确认基准。批量同步沿用单条同步的冲突与恢复交互，取消或失败时停止后续记录，保留已完成结果。
- 单条已关联记录按远端记录 ID 查询核对；批量同步共享首次完整表格读取，不对每条一致记录重复请求，已有记录按批次 ID 重新核对、提交并校验成功响应，不在正常运行中回读记录。
- 成功码不能代替记录 ID 与全部提交字段的校验；缺失字段不当作空值，批量响应中缺失或不符的行保持待同步，有效行独立确认。
- 写入响应的单选、多选 ID 通过字段选项映射为文本；遇到未知 ID 时每次写入或整批响应最多额外读取一次字段配置，不读取记录、不重写，刷新后仍不兼容或无法解析则保持待同步。
- 确认基准仅更新已提交并验证的字段，未提交字段沿用写前读取值，不把响应当作完整查询快照。在线测试额外回读验证响应与实际保存结果一致。
- 未绑定记录匹配与不确定新增恢复仍读取完整表格；人工交互后废弃旧快照，失败不自动重试，后批失败不撤销前批已完成确认。

## 新增结果不确定时的恢复

- 不确定新增的候选按发起请求时保存的地图名与 Mod 元数据名匹配，排除已经关联的远端 ID；只有用户明确选择且重新读取后仍有效的候选才能绑定，绑定本身不确认同步。没有候选不等于新增失败；解除保护须单独确认请求已结束且远端未新增，并再次读取检查。

## 体验顺序与拖动预览

- 正式记录编号是可明确修正的体验顺序，而非身份键；普通编辑与采用远端不单条改号。顺序调整须预览、检查编号快照并事务重排，仅置换现有编号集合，不压缩空缺，不改变内部主键、表格关联或计数器。受影响编号作为公开字段进入待推送和正常核对；失败保留本地调整，未通过写入响应校验不确认。表格通过隐藏数字编号列和升序自动排序视图显示顺序，不能把查询排序当作视图配置，不交换内容或删除重建来模拟移动。未编号登记始终在末尾，不能参与编号移动。
- 行拖动释放后只请求移动确认，确认前不修改数据；与编号输入入口复用同一事务及同步流程。拖动按稳定记录 ID 而非可见行号定位，筛选后的移动仍对完整序列预览；列宽拖动与普通点击不退化，拖动后的合成点击不得误开编辑器。无效落点、取消及 Esc 均释放鼠标捕获，不移动未编号项。
- 行拖动直接在列表内预览最终排列，保持原编号和内容；按原始位置计算落点，避免移过来的源记录使预览反复跳动。预览中的选中项按稳定 ID 获取；取消、无效落点或刷新筛选时恢复原排列，不能提前写入数据。

## 日期与复选框

- 用时在记录模型中为 `Duration | None`，SQLite 显式编解码为非负的 100 ns 整数 ticks；编辑器显示与解析统一使用 `Duration` 默认游戏计时器格式，不引入记录专用精度格式。显示文本未变时保留原始时长，不因保存其他字段而丢失显示之外的精度；明确改写才重新解析。表格编码与核对使用截断到整秒的 `H:MM:SS`。采用远端时，整秒文本相同不得丢弃本地亚秒精度，实际变化或清空才替换本地值；同步基准与快照仍使用表格协议表示，不能迁移成 ticks。

- 体验记录的起始日期、结束日期与 Mod 更新时间统一使用纯日期，表格时间戳按系统本地时区解释后提取日期，写出时编码为该日期的本地零点；日期选择器默认值、地图更新时间的日期提取和记录创建日期的显示同样使用本地时间，但创建时间戳仍以 UTC 保存。不得硬编码 UTC 或 UTC+8，也不得用当前时区偏移代替目标日期的本地时区规则。
- 复选框在表格读取边界将空值解码为 `False`，本地磁带字段统一为默认 `False` 的非空布尔值，不保留未知状态或比较层特判。
- 边界测试须包含与本地编码不同的真实远端表示及跨 UTC 日期边界的时间戳，避免直接回填编码结果掩盖读写不对称。
