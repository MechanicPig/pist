# 地图预览约束

## 双端协议与路线保存

- Berries 默认仅使用包内实体与入口规则；Pist 负责本地覆盖的发现与合并。预览入口加载一次规则，将同一份结果传给初始布局和后续导航，避免第一张地图与跳转目标使用不同来源或不同时刻的规则；审计中的地图预览也遵循应用的规则来源。
- 浏览器地图预览的 JSON 状态、操作请求和静态前端必须成对修改；协议测试覆盖字段和行为，不以中文 UI 文案的逐字匹配替代功能测试。
- 初见单房间和累计时间由后端以完整精度计算，投影为游戏秒级格式（`GAME_TIMER_SECONDS_FORMAT`）的 `firstClearTime` 与 `firstClearCumulativeTime` 文本；前端仅切换和展示，不重复解析 ticks、累加或格式化。缺失用时不等于零，累计前缀遇到缺失房间用时时停止。
- Pist 预览通过 `FirstClearStats` 查询函数获取数据，不直接依赖具体 Mod 的存档容器；应用负责读取 Ender's Blender 文件及协议键编码。每个已解析地图身份在本次预览中缓存一次查询，跳转失败不替换当前页面。
- 路线保存先持久化候选结果，成功后才更新页面保存基准，并通知对应地图的已打开记录编辑器回填加权主房间数；空路线留空，不覆盖其他未保存字段。写入失败须返回 JSON 错误，不触发回填，并保持取消操作和重新打开时的原保存结果。
