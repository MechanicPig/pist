# 实体审计约束

## 收录与分类证据

- 实体审计数据库维护整库知识，不按报告或扫描批次隔离。报告 JSON 仅作为导入格式；扫描导入与地图浏览中的待审查组合均增量收录，按完整属性、元数据和来源去重，保留人工结论以及属性缺失／显式默认值的差异。重复实体 ID 由地图检查报警，不引入同值实例序号。弹出规则阻断窗口前先持久化实际组合；收录失败须显示错误，不让用户进入无法确认数据的工作流。
- 分类确认覆盖按移除已审查为无关属性后的组合计算，UI、规则生成和运行时检查复用该覆盖证据。等价变体可沿用明确分类结论，但派生证据不能伪装成新的持久化人工记录；未覆盖的相关属性组合、明确冲突或等价组合中的矛盾类别仍须人工审查。
- 已收集实例与规则的核对属于 Berries 通用能力，返回实体不存在、未匹配或明确排除三种问题；完整检查结果同时保留成功匹配的实体、规则与元数据，让调用方补充策略而不重复扫描。`pist.entities.collected` 只负责读取人工审查证据和提示优先级：直接复用公共问题，仅以独立的 `UnreviewedCollectedEntity` 表示未审查变体，两者组成联合类型，不复制公共问题模型或枚举。只为实际找到的已收集实体批量读取证据，未审查变体优先于规则匹配结果。Berries 不接收审计回调或定义人工审查状态，不为省去应用适配而迁走通用核对能力。

## 覆盖检查与规则提交

- 当前禁用本地分类定义，普通审计界面只允许选择共享分类；新增、修改、重命名和删除分类仅在显式共享维护模式开放。规则存储同样拒绝普通模式中的分类变更，不只隐藏 UI 入口；本地实体规则覆盖仍可引用共享分类。
- Berries 提供规则 TOML 解析、明确文件读取、包内默认加载、模型校验、显式层合并、引用变换与序列化，不发现用户规则或决定保存位置，不承担分类变更的文件及数据库协调。Pist 通过 `pist.entities.config.EntityConfigStore` 发现和保存本地覆盖，不提供共享发布或分类维护方法；共享维护使用 `pist.entities.maintenance.EntityRuleLibrary`。规则保存、发布及分类变更均使用 UTF-8 普通写入，多个文件依次写入，不自动备份、回滚或重试；不向公共包搬回应用存储策略，也不向普通配置存储添加维护模式标志。

- 候选列表在后台检查完整规则覆盖，标记未完全覆盖项，并在补审后更新。刷新时列出未覆盖候选，允许返回补审或忽略提示继续；继续后正常预览并替换完整生成规则层，不针对已有规则特殊保留或删除。规则预览后生成结果变化时须重新确认差异。
- 类别重命名、删除先写规则文件，再通过审计数据库自身事务修改引用，不提供跨文件及数据库的原子性或自动文件恢复。失败时明确告知文件可能已部分或全部写入，提示检查 Git diff 与数据库引用，由开发者手动处理；不得声称规则文件已恢复。仅在整个操作成功后更新 UI 内存。
