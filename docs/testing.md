# 测试维护

## 选择验证范围

日常修改先根据调用链选择相关测试文件或 `-k` 用例，默认串行运行；跨领域影响无法界定、阶段集成和发布前再运行全量。删除或迁移接口时，先通过引用搜索和 Pyright 检查调用方，再补充相关运行测试，不仅因涉及多个文件就启动全量。

```sh
# 专项验证，按改动替换测试路径
uv run --all-packages pytest pist/tests/test_save_switch.py --basetemp .pist/tests/pytest

# 全量并行验证
uv run --all-packages pytest -n auto --dist worksteal --basetemp .pist/tests/pytest

# 串行复现并统计慢测试
uv run --all-packages pytest -n 0 --basetemp .pist/tests/pytest --durations=30
```

测试运行产生的临时文件、隔离环境与验证产物统一放在 `.pist/tests/` 下，测试源码仍保留在既有测试目录。执行前确保 `.pist/tests/` 存在。普通测试（包括单包测试）通常复用 `.pist/tests/pytest`，不为每次运行建立新目录。`--basetemp` 会被 pytest 清空，只能指向该根目录下的专用子目录；不得直接指向 `.pist/tests/`、数据目录、仓库根目录或复用其中的业务文件。

## 权限与临时目录生命周期

高权限测试使用独立的 `.pist/tests/pytest-admin`，不得复用普通测试目录。在 Windows 上，高权限进程创建的 pytest 临时目录可能具有普通进程无法访问的访问控制列表（ACL，即规定哪些用户或用户组可以读取、修改等的权限规则）；避免在两个权限级别之间共用 `--basetemp`，而不是在出错后反复另选目录。普通目录出现访问被拒绝时先排查占用和权限，不能把换目录当作问题已经修复。需要管理员权限时，由用户确认 Windows 用户账户控制（UAC）的提权弹窗。

一次性验证需要的其他专用目录也必须位于 `.pist/tests/` 下，运行前明确用途与清理责任。测试结束后，无诊断或复现保留需求的专用临时目录、安装验证环境及产物应及时清理；需要保留时说明原因和路径。主动清理遵循 AGENTS.md：移入系统回收站，失败则移到 `.pist/recycled/` 下独立保留，最终由用户清理，不永久删除。高权限测试的目录由同一高权限进程在结束后清理，失败时也应尝试清理；先确认准确目标且不跟随符号链接，不扩大到测试根目录或链接指向的外部资源。普通共用的 `.pist/tests/pytest` 可留待下次 pytest 重建，pytest 自身的临时文件生命周期不变。

### 2026-10-22 Windows 权限复现

环境为本机 Windows、CPython 3.14.7、pytest 9.1.1。普通权限与经用户确认提权的管理员进程在 `.pist/tests/` 下使用隔离样本；没有修改旧故障目录的权限。结果如下：

| 创建方式 | 后续普通权限进程的结果 |
| --- | --- |
| 普通权限运行 pytest，再复用同一 `--basetemp` | 连续两次测试通过，能够清理重建 |
| 管理员进程以默认 mode 创建目录 | 能枚举目录 |
| 管理员进程以 `mode=0o700` 创建目录 | 枚举时报拒绝访问 |
| 管理员运行 pytest，再由普通权限 pytest 复用其 `--basetemp` | 清理阶段报 `PermissionError: [WinError 5]`，测试体尚未执行 |

当前 pytest 的 `TempPathFactory.getbasetemp()` 对显式 `--basetemp` 先清理已有目录，再调用 `mkdir(mode=0o700)`。本次管理员创建的 `0o700` 目录与 pytest 目录的所有者均为 `BUILTIN\Administrators`，权限继承关闭，访问规则只授予所有者、System 和 Administrators 完全控制；同一账户的普通权限进程不能借助管理员组获得访问。普通权限创建的 pytest 目录虽然也关闭继承，但所有者为当前用户，因此可以复用。管理员创建的默认 mode 目录则保留父目录继承权限，普通权限仍可访问，所以不能将问题概括为“管理员创建的目录都不可访问”。

该实验证明管理员运行 pytest 后复用临时目录足以触发同类故障；旧 `.pist/pytest` 的当前所有者与完整权限尚未读取，不能把复现结论当作对旧目录原因的最终确认，也不宣称旧目录已修复。高权限实验目录已由管理员进程清理；普通样本与报告最初的直接删除命令被执行工具的安全策略在启动前拦截，未收到具体拦截规则，这与 Windows 返回访问被拒绝是两种不同的失败，不应混为一谈。经用户确认，普通样本、报告与本次临时实验脚本随后成功移入 Windows 回收站，可由用户恢复，未使用永久删除或修改目录权限。

## 并行与隔离

全量使用 `-n auto`，由 xdist 自动选择 worker 数；小范围测试不默认并行，避免进程启动和每个 worker 重复收集的开销。`auto` 是按核心数选择进程数，不会根据实时负载动态调整；有 `psutil` 时优先识别物理核心数，否则使用 xdist 的回退检测，不为此额外添加依赖。使用 [xdist 的 worksteal 调度](https://pytest-xdist.readthedocs.io/en/stable/distribution.html)在不同耗时的测试之间分配工作，不按文件分组让大型 UI 测试模块独占一个 worker。

- 同一工作树同一时间只有一个会话执行测试，多会话通过独立工作树并发，不另外协调测试目录。单次 pytest 负责创建和调度全部 worker，各 worker 在 `--basetemp` 下使用独立的 `popen-gw*` 目录。
- 可写文件、SQLite、设置、规则与锁文件使用各测试的 `tmp_path`，不把可变数据库提升成跨测试共享的 fixture。共享合成游戏资源只读使用。
- 地图浏览测试的默认 `DataStores` 工厂使用测试临时库；Pist 测试另有自动保护，发现 `SQLiteStore` 指向实际 `LOCAL_DATA_PATH` 时在连接前失败。子进程不继承 pytest 的 monkeypatch，须显式传入隔离路径或环境；不得依赖此保护替代子进程隔离。
- 预览服务绑定 loopback 的端口 0，由系统分配端口；测试退出时取消并等待服务任务，不能为并行固定分配某个端口。
- 环境变量和模块替换通过 `monkeypatch` 恢复；worker 之间由进程隔离。新增 session/module fixture 时须检查其是否会被每个 worker 重复执行，以及是否共享可写状态。
- 腾讯表格在线测试仍需显式配置 `PIST_TEST_SHEET_URL`，默认全量测试和 CI 均不写远端。上述并行验收未启用在线测试，也不证明多个在线写入任务可共用测试表。

## 2026-10-16 耗时对照

环境：Windows 11、Python 3.14.7、pytest 9.1.1、pytest-xdist 3.8.0，开发机有 24 个逻辑核心；使用同一 workspace 环境及本地磁盘，各轮顺序运行，不同时启动其他检查。下列为 pytest 报告的运行耗时，不包含依赖安装；仅代表本机此次样本，不作为 CI 精确耗时阈值。

| 方式 | 结果 | 耗时 |
| --- | --- | --- |
| 原串行基线 | 1154 通过、1 跳过 | 186.00 秒 |
| 2 worker，worksteal | 1154 通过、1 跳过 | 92.39 秒 |
| 4 worker，worksteal，补齐默认数据库隔离后 | 1157 通过、1 跳过 | 49.22 秒 |
| 4 worker，重复运行 | 1157 通过、1 跳过 | 49.29 秒 |
| 8 worker | 1157 通过、1 跳过 | 29.21 秒 |
| 12 worker | 1157 通过、1 跳过 | 25.84 秒 |
| auto，实际选择 12 worker | 1157 通过、1 跳过 | 27.36 秒 |
| 24 worker | 1157 通过、1 跳过 | 21.97 秒 |
| 24 worker，重复运行 | 1157 通过、1 跳过 | 23.09 秒 |

4 worker 起增加了 3 项测试隔离保护回归，并将原先隐式打开工作区数据库的浏览器测试改为临时库；未删除原有测试或缩减大批量样本。本机此次测量以 24 worker 最快，但不将本机核心数硬编码给其他机器；按用户选择，全量验证和 CI 默认使用 `auto`，Berries 的独立环境验证仍串行运行。本次虚拟环境中有未在项目声明的 `psutil`，因此 `auto` 选择了 12 个物理核心；干净锁定环境的选择可能不同。

慢项主要是批量同步中的真实 SQLite 准备与事务写入（串行单项约 3～5.5 秒），以及多步骤 Textual 鼠标、布局和重开交互。`linked_records` 在确认后再次保存，是刻意构造待推送记录，不是可以直接删除的重复写入；不把它改成共享可变库、关闭持久化保证或减少批量边界样本。预览关闭后的连接拒绝验证在 Windows 上也约需 2 秒，仍保留真实监听器释放检查。

本次未通过缩短框架等待、跳过动画或去掉真实点击来获取加速。后续若继续优化，先用 `--durations` 找热点，再单独 profile 并做相同工作量对照；固定休眠仅在存在可等待的完成信号时替换，不能以更脆弱的时序断言换取耗时下降。
