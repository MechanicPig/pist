# 公共能力包与个人应用分层路线图

本文记录 Pist 与公共 PyPI 包 Berries 的架构结论、原始差距和实施进度。
它是实施时的复查清单，不代表当前源码已经完成这些边界。

最后更新：2026-09-28。

## 背景与目标

当前 Pist 的完整工作流面向个人使用：记录模型、腾讯智能表格字段和部分交互都服务于一套
特定的数据结构。其他开发者可能不编辑表格，或者拥有完全不同的表格结构，因此不应把
当前个人工作流抽象成一个所谓的通用表格框架。

长期目标是形成两层依赖结构：

1. 一个可发布到 PyPI 的公共 Celeste 能力包，提供稳定、易用且与具体应用无关的接口。
2. 建立在公共包之上的应用，包括个人记录应用和独立的实体规则审计应用。

公共包的范围不等于把当前 `game/` 目录原样发布。它可以包含建立在游戏数据之上的稳定
公共能力，例如 GameBanana 查询和基础地图预览，但不能包含个人工作流的编辑语义。

## 已确定的边界

### 公共能力包

公共包负责提供可复用的 Celeste 事实、读取能力和基础展示能力：

- 游戏目录、原版内容、已启用 Mod 和存档读取；
- Campaign、Level、Map 等领域模型；
- `.bin` 地图按需解析；
- Dialog、Collab 及其他构建地图目录所需的游戏或 Mod 元数据；
- 随包发布和更新的实体识别规则、类别层级与分类结果；
- 基于规则配置的地图入口识别；
- Collab Lobby 基础识别；
- Ender's Blender 存档解析；
- 地图房间、tile、实体、出生点等客观布局数据；
- GameBanana 元数据查询；
- 只读的基础浏览器地图预览。

公共包中的外部输入继续在边界处校验，并对网络、文件、ZIP 和 loopback HTTP 服务提供
明确、可诊断的错误。扫描和浏览过程不得无条件解析全部地图。

公共包内部区分“Celeste 原版格式与磁盘事实”和建立在其上的“Everest 激活、覆盖与 Mod
组合语义”，后者只能依赖前者。这是内部依赖边界，不拆成两个发行包或两套面向不同用户的
并列 API；在出现真实的纯原版消费者前，不新增专用原版入口。

### 个人应用

个人应用负责所有带有当前使用者意图、记录规则或目标表格结构的能力：

- `MapRecord` 及个人首见记录字段；
- 路线选择、房间重复次数和路线草稿；
- 首通路线、房间死亡与时间叠加；
- 收集品屏蔽和人工校正；
- 个人实体统计规则及其记录字段投影；
- GameBanana 数据到个人记录字段的投影；
- 本地个人记录和路线持久化；
- 腾讯智能表格字段映射、报告和同步；
- Textual 中围绕上述工作流组织的界面；
- 个人凭证、表格标识和其他应用配置。

个人应用可以使用公共包返回的事实，但公共包不得导入个人应用的模型、存储或 UI。

### 实体规则、分类与审计

实体规则库属于公共包，并作为包内共享数据随版本更新。公共包负责：

- 按精确实体 ID、属性和地图 metadata 匹配规则；
- 提供实体类别层级、label 和 sprite；
- 返回带有 kind 和来源信息的分类实体及保守诊断；
- 加载调用方明确指定的本地规则覆盖。

实体分类本身不应决定如何统计。目前 `EntityKind.stat`、`EntityKind.table_field` 和
`EntityKind.select_value` 同时表达统计方式、个人表格目标和个人输出值；`stat_owner()` 还会沿
类别父级继承这种统计语义。它们都应从公共类别规则中移除。

个人应用应拥有一份独立、受版本控制的实体统计规则文件。它引用公共 kind，定义按某个 kind
或其子树进行 count/exist/select 等聚合、select 输出值以及目标记录字段。该文件属于个人应用，
不作为公共包数据发布，也不同于用户放在 `.pist` 下的本地实体识别覆盖。

`MapEntityStats`、`SelectConflict` 和 `RecordValues` 投影随统计规则进入个人应用。公共包只提供
分类实体；个人应用根据自己的统计规则产生记录值和完成度判断。基础地图预览可以显示公共分类
标记，但统计摘要属于个人应用叠加层。

本地规则覆盖是高级能力，不是跨包版本稳定的数据格式。文档和加载诊断必须明确提示：升级公共包
后，旧的本地规则不保证仍与新的共享类别、识别规则 schema 或合并语义兼容。更新后必须重新校验；
无效或冲突的本地规则不得静默忽略或被共享规则覆盖。

个人统计规则也必须在公共包更新后重新校验其 kind 引用。公共 kind 被删除或重命名时应形成明确
诊断，但个人统计规则的格式和迁移由个人应用负责，不属于公共包兼容承诺。

实体审计不属于公共包或个人记录应用。它应成为另一个依赖公共包的独立应用，负责扫描语料、
保存证据、审核未知实体以及生成或维护共享规则。公共包可以保留运行时规则诊断，但不包含审计
数据库、推断工作流或审计 UI。

### 不进入公共包的路线能力

`MapRoute` 不是公共能力。基础预览的职责是展示地图，而不是定义用户如何选择路线、如何
计算房间次数或如何修正收集品统计。因此公共包不提供 `RouteStore`，也不把路线编辑包装
成通用扩展框架。

当前 `routes.py`、路线 SQLite 数据和路线编辑协议最终都应由个人应用拥有。

## 地图预览的具体边界

公共地图预览应保持只读，可包含：

- 房间、前景与背景 tile、实体和出生点渲染；
- 平移、缩放、适应画布、房间搜索和定位；
- 查看实体 ID、属性及其他客观信息；
- 在不引入路线语义的前提下，展示地图入口；
- loopback 服务、静态资源以及与只读状态对应的浏览器协议。

以下能力属于个人应用的地图编辑器：

- 房间选择；
- 房间重复次数；
- 首通顺序、死亡和时间叠加；
- 收集品屏蔽；
- 收集品统计摘要中的人工校正状态；
- 编辑/预览模式切换；
- 保存、取消和未保存变更检查；
- 从个人数据库读取路线或把编辑结果写回数据库。

按当前协议，至少下列状态字段不能保留在公共预览契约中：

- `selected`
- `roomCount`
- `firstClearRooms`
- `firstClearDeath`
- `firstClearTime`
- `excluded`
- `readOnly`
- `initialMode`

至少下列操作端点属于个人编辑器，而不是公共预览：

- `/save`
- `/cancel`

`/open`、`/back`、`/forward` 和 `/home` 已纳入首版基础预览，用于只读的跨地图入口导航，
不具有路线编辑语义。

前端也必须沿同一边界拆分。地图画布和对象查看可以复用；路线选择、次数输入、屏蔽按钮
和保存状态只能存在于个人应用。不要为了复用当前编辑器而在公共包中预先设计通用插件
系统。

## GameBanana 边界

GameBanana 查询属于公共包中的可选外部元数据能力。公共接口应负责：

- 按 Everest Mod 元数据名查询提交；
- 校验外部响应并返回精确的不可变模型；
- 区分未找到、找到唯一结果、结果冲突、网络失败和无效响应；
- 不依赖个人记录字段、Textual 控件或腾讯智能表格。

把查询结果转换为“作者”“Mod 名”“更新时间”等个人表格字段，属于个人应用的投影逻辑。

## 实施前源码的已知差距

以下是开始实施前确认并用于指导拆分的主要耦合；已完成项以阶段清单为准：

- `map_preview.server.MapPreview` 直接依赖 `MapRoute` 和 `LocalDataStore`；
- `MapPreview` 同时承载只读查看、路线编辑、收集品屏蔽和持久化；
- 地图预览的 Python 状态、HTTP 协议和 JavaScript 都混合了公共与个人字段；
- `LocalDataStore` 同时存储个人 `MapRecord`、路线和 Collab 扫描缓存；
- `LocalDataStore` 因 `MapRecord` 依赖而不能被公共预览安全引用；
- 当前单个发行项目同时依赖 Textual、keyring、aiohttp 等公共与应用依赖；
- 顶层 `pist.__init__` 尚未提供经过设计的公共库入口。

`gamebanana.py` 当前基本不依赖个人记录或 UI，可以作为公共能力继续演化；个人
`records.py` 对 GameBanana 模型的使用不构成反向依赖。

实体分类当前存在一组明确的应用耦合：`kinds.toml` 同时保存公共类别与个人 `stat`、
`table_field`、`select_value`；分类模块随后直接生成 `MapEntityStats` 和 `RecordValues`。应拆成
公共实体类别/匹配规则与个人实体统计规则，避免公共包替其他应用决定统计口径。

## 目标依赖方向

目标依赖只能由个人应用指向公共包：

```text
个人记录应用       实体规则审计应用
          \       /
           \     /
       公共 Celeste 能力包
                 │
                 ▼
 游戏文件 / Mod / 存档 / HTTP / 浏览器
```

公共包不得导入以下个人概念：

- `MapRecord`
- 腾讯智能表格模型或客户端
- 个人路线、草稿和记录数据库
- Textual 页面或控件
- 个人凭证和表格配置
- 审计数据库、规则推断工作流或审计 UI

公共包内部仍可按 `game`、`entities`、`map_layout`、`map_entrances`、`gamebanana` 和
`map_preview` 等职责划分模块。这些内部模块不构成额外的产品层级。

## 公共包验收标准

满足以下条件时，才认为公共层已经具备独立发布条件：

- 其他开发者无需导入 Textual、腾讯表格或个人记录模型，即可扫描 Celeste 和 Mod；
- 可以通过稳定、带类型的接口选择 Campaign、Level 和 Map，并按需读取地图内容；
- 可以读取原生及受支持的 Mod 存档，并获得带来源信息的实体分类结果；
- 可以使用随包更新的实体与地图入口规则，并显式加载经过校验的本地覆盖；
- 可以独立查询 GameBanana，并处理未找到、冲突和网络错误；
- 可以启动只读地图预览，且该预览不出现路线或收集品校正语义；
- 公共包的测试不需要个人数据库、表格凭证或腾讯智能表格；
- 个人应用仍能完成现有记录、路线编辑、校正和表格同步工作流；
- 至少有一个小型示例展示如何用公共包构建不同于当前个人表格工作流的应用。

一个具体约束是：第三方应用应能在较少的业务代码中完成“扫描游戏、选择地图、读取存档或
实体信息、输出自有格式或打开基础预览”，而不需要复制 Pist 的内部组装流程。

## 暂不实施的方向

在出现第二个真实消费者和明确共同需求之前，不做以下抽象：

- 通用表格 schema 或字段配置框架；
- 通用 UI 插件系统；
- 为路线编辑设计公共扩展协议；
- 为了物理拆包而提前复制模型或维持双向兼容层；
- 将所有当前内部模块一次性承诺为稳定公共 API。

## 当前实施说明

- 公共只读预览位于 `berries.map_preview`，个人路线编辑器位于 `pist.route_editor`，两者拥有
  各自的服务端协议与静态资源。
- 原 `LocalDataStore` 已删除；`RecordStore`、`RouteStore` 与 `CatalogCache` 保持原数据库路径
  和原表结构，因此本次不涉及 schema 迁移。
- 顶层 `berries` 只导出刻意选择的公共入口；`examples/list_maps.py` 展示了不依赖个人表格
  模型的第三方使用方式。
- `berries` 安装后的本地覆盖使用 `BERRIES_DATA_DIR` 或平台用户数据目录；源码 workspace 中
